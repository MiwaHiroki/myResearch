# #30 から続くissueの案

issue #30（写真ごとに1回のクリックからN本の溝を抽出し、N周分の音声を作る）の作業中に出た、続きの作業の案。issueのひな型（`.github/ISSUE_TEMPLATE/`）に沿って書き起こすときの材料にする。

## 案A：自動追跡のパラメータの再考（振幅が1付近になる外れ値）

- ラベル: `feature`（または `bug`。ユーザーが選ぶ）
- ゴール: 正規化した振幅が1付近になる外れ値（画像の上で真の位置から1〜2 px ほどのずれ）を減らすよう、自動追跡（`trackGroove`）のパラメータを考え直す。
- 背景: #30 の評価（2026-11-04）で、ユーザーが U1・U2 を確かめたときに見つけた。外れ値は本実装（`cycleResult_origD_hist5_1104.mat`）にも、ユーザーが40回クリックした正解データ（`cycleResult_origD_track5_1104.mat`）にもあるので、ヒストグラムによる溝の選択ではなく、自動追跡で生じたものとユーザーが判断した（**別のissueで検討すると決定**）。
  - 2〜5本目は、本実装（帯）と正解（追跡）が64本中63本で完全に一致したので、両者は同じ点を選んでいる。外れ値がどの段階（点群の検出 `GrooveExtractor`、追跡の `Tolerance`・`FitLength`、デトレンド）で生じるかは、このissueで確かめる。
  - 重心法の wav では、±1 を超えた32サンプルが切り捨てられた（`AMP_DIV = 1.5`、plan.md Q3 で記録だけにすると決定）。外れ値との関係は確かめていない。
  - 正解と同じ処理を含むデータとの比較では、この種の誤りは見つけられない（[`retrospective.md`](./retrospective.md) 4章の5、7章の C1）。評価には、正解に依らない確かめ方（振幅の外れ値の数、隣の列との y の跳び など）が要る。
- 使えるデータ: `experiments/1104/` の2ファイル（5周分）、`experiments/1014/cycleResult_origD_track_1014.mat`（#25 の1周分）。
- 未決事項の候補: 外れ値の定義（振幅のしきい値、y の跳びの大きさ）、変えるパラメータの範囲、評価の正解（手動で直した経路を作るか）、#25・#30 の結果を作り直すか。
- 作るタイミング: #30 のPRがマージされた後（`grooveHist_Ncycle.m`・`grooveTrack_Ncycle.m` と 1104 のデータを使うため）。

## 案B：高解像度化した画像（intpD・rsmplD）でのN本の抽出

- ラベル: `feature`
- ゴール: `dInterp`・`dResample` で高解像度化した画像でも、`grooveHist_Ncycle.m` と同じ方法でN周分を作れるようにする。
- 背景: #30 では高解像度化なし（origD）だけを扱った（issue の「将来は `rsmplD`・`intpD` でも同じ実験をする」）。#25 の [`follow-ups.md`](../closed/25-groove-tracking/follow-ups.md) の案B（1本の自動追跡の高解像度化）も、まだissueになっていない。関数は長さの引数をpxで持つので、高解像度化した画像にも使える前提で設計してある。
- 未決事項の候補: #25 の案Bとまとめるか、`BIN_WIDTH`・`BAND_TOL` を高解像度化した画像で決め直すか、正解データ（`grooveTrack_Ncycle.m`）も高解像度化して作るか。
- 作るタイミング: 案Aの後がよい（追跡のパラメータが変わると、高解像度化した画像での値も決め直しになるため）。

## 案C：周の順を、針で再生した音と比べて確かめる

- ラベル: `feature`
- ゴール: N周分の音声の周の順（j本目の写真8の次に j+1本目の写真1が続くこと）を、針で再生した音（`data/stylus_playback/Audio 1_01.wav`）との相互相関で確かめる。
- 背景: issue #30 の「提案」の P4。写真どうしに重なりが無いため、周の順は数値では確かめられなかった（plan.md 2.3 の15）。正解データも同じ並び順を前提に作るので、正解との比較でも見つけられない。#30 ではユーザーが波形とスペクトログラムから判断した（U3）。周の境目は聞いても感知できなかった。
- 未決事項の候補: 比べる区間（周ごと・写真ごと）、`fs` の違いの扱い、`scripts/evaluation/stylus/` の既存の比較との関係。
- 作るタイミング: #30 のPRがマージされた後。急がない。

## 参考：issue の「提案」のうち、採用しなかったもの（issueにするかはユーザーが決める）

- **P1：2本目以降も `trackGroove` で追跡する。** 今回は、帯で取り出す方法が正解の作り方と64本中63本で完全に一致したので、差は小さい。案Aで追跡のパラメータを変えたときに、比べる候補になる。
- **P2：山の間隔を確かめる**（issue の「任意」の要求仕様）。実装していない。このデータでは間隔が中央値の ±5% 以内なので、1.5倍・0.5倍の判定はどちらも起きない（plan.md 3.1）。他のレコードやNを増やすときに足す。

- **P5：正解データのクリックを減らす**（1本目に保存したクリックを使う）。正解データ用スクリプトに `GUIDE_RESULT_PATH` を足したので、クリックの負担は減っている。
