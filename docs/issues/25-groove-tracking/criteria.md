# #25 写真1枚の範囲で1本の溝を自動追跡する — 評価基準

## 1. 結論（判定の決め方）

- **合格**：前提（P1・P2）を満たし、テスト（T1・T2）と数値の項目（E1〜E6）をすべて満たし、ユーザーが判断する項目（U1〜U4）でユーザーが良いと判断したとき。
- **ユーザー確認待ち**：P・T・E をすべて満たし、U が残っているとき。評価レポートはこの判定で出し、見てほしいファイルと観点を書く。
- **不合格**：T・E のどれか1つでも満たさないとき。どの写真・セグメント・列でどう外れたかを評価レポートに書き、実装に戻す。
- **評価の保留**：前提 P1・P2 を満たさないとき（基準データが想定と違う）。実装の誤りではないので、不合格にはせず、メインに報告して止める。
- 基準は実装の前に決めたもので、実装の結果に合わせて変えない（`docs/rules/evaluation.md`）。デトレンドの次数（Q2）をユーザーが評価の後に変えた場合は、E4・E3 のしきい値を決め直して承認を取り直す（5章 Q-b）。

### 検討の記録（未決事項だったもの）

**Q-a. E1b（セグメントごとのRMSEの最大）のしきい値**
- 背景：重心法は、基準データの再現性の限界（0.162px）をそのまま使える（試作 0.087px）。局所的最大値法は、手動側が固定幅の外の点を落とすため、試作でも k=68 で 0.278px になる（追跡側の誤りではない）。
- 選択肢：
  - (a) 重心法 0.162px、局所的最大値法 0.30px（**今の仮の値**）：試作の値は通る。局所的最大値法の余裕は 0.02px と小さいが、試作と同じ点を採れば同じ値になる。
  - (b) 両手法とも 0.30px：重心法の判定がゆるくなる。
  - (c) 両手法とも 0.162px とし、超えたセグメントは「手動側が落とした点による差か」を評価担当が列ごとに確かめて、そうであれば合格とする：理屈は一番通るが、判定に評価担当の解釈が入る。
- 推奨：(a)。数値だけで判定でき、試作の結果（plan.md の決定の根拠）と矛盾しない。外れた場合も E1c（相関 ≥ 0.70）と U1 の図で、別の溝かどうかは分かる。
- 止めるか：止めない（評価の段階までに決まればよい）。

**Q-b. E4（最終出力と手動の再現の比較）を判定に使うか**
- 背景：E4 の差の大半は、デトレンドの違い（写真ごと9次とセグメントごと3次）によるもので、追跡の誤りではない（追跡そのものは E1 で見る）。ただし、最終出力の組み立ての誤り（分け直しのずれなど）を拾える。しきい値は9次を前提にしており、次数を3や5に変えると満たさない（3次：相関の最小 0.658）。
- 選択肢：
  - (a) 判定に使う（今の案）。次数を変えたら、E4 のしきい値を決め直して承認を取り直す。
  - (b) 報告だけにする。組み立ての誤りは E5c・E5d（整合の確認）で拾う。
- 推奨：(a)。9次のままなら試作の値に十分な余裕があり、組み立ての誤りへの二重の確かめになる。次数を変える場合はどのみち評価をやり直すので、そのとき決め直せばよい。
- 止めるか：止めない。

## 6. 仮定と、気づいた点

- 仮定：評価の段階では、追跡と手動の再現を同じ日に作る（日付は評価スクリプトの `TRACK_DATE`・`MANUAL_DATE` で別々に指定できる）。図・wav・表の出力先は `OUT_DATE`。
- 仮定：E1 で手動の再現と同じ前処理をかけるときの次数は、手動の再現の `conditions.polyDegree`（3）を使う。
- 気づいた点（メインへの申し送り）：試作で写真ごと9次をかけ `AMP_DIV = 1.5` で割ると、振幅の最大が重心法で 1.03 になり、±1 を超える。`AudioData.saveAudio`（`audiowrite`）が書く wav ではその部分が切り捨てられ、警告が出る見込み。plan.md の仮定A2（既存と同じ `tol/2` で割る）は承認済みなので評価基準には入れていないが、U3 の試聴に影響しうる。実装担当の報告で警告の有無を確かめてほしい。→ ユーザーの判断で、このままにする（5章）。
