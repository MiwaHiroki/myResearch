## 2. 調査結果

### 2.1 外れ値が生じる段階（plan.md 2.2 の要約）

この文書の言葉を先に決める。

- **溝底区間**：写真の各列で、暗さ（1 − 画素値/255）がしきい値 `D_THRESH`（0.6）以上の行が続く範囲。溝底の候補になる。
- **幅**：溝底区間の最後の行 − 最初の行 [px]。3行の区間なら幅2である。`GrooveExtractor.findGrooveBottomIntervals` は、幅が `WIDTH_THRESH` 以下の区間だけを溝底点にする。
- **重心法**：溝底区間の行を、暗さで重み付けして平均した y を溝底点にする方法。**局所的最大値法**：区間の中で最も暗い行を溝底点にする方法。
- **局所的なずれ**：選んだ点のデトレンド前の y から、前後10列（合わせて21列）で点を採れた列の y の中央値を引いた値。

外れ値は、溝底点の検出の段階で生じる。

1. 溝底の暗い線のすぐ隣に、暗さがしきい値すれすれの行が続いていることがある。この行がしきい値をわずかに上回ると、溝底区間がそこまでつながり、幅が5以上になる。
2. 重心法では、しきい値すれすれの行も、溝底の行とほぼ同じ重みで効く。そのため、区間が片側に1行広がるごとに、点がその側へ約 0.45 px ずれる。
3. 1104 hist で選んだ点のうち、局所的なずれが 1 px を超える26点は、すべて幅5以上だった。幅4以下の点のずれは、最大 0.967 px だった（plan.md 2.2 の1の表）。
4. 溝の選択（自動追跡の `Tolerance` = 2 px、帯の ±3 px）は、許す範囲がずれより広いので、その点を採る。デトレンドは原因ではない（plan.md 2.2 の3・4）。
5. 局所的最大値法の点は、区間が広がっても溝底の線の上に残るので、ほとんどずれない（plan.md 2.2 の5）。

### 2.2 物理的な原因の考察（ユーザーの指摘で直した）

- このプロジェクトで溝形状として取り出しているのは、溝の底の部分である。今回の外れ値は、すべて、**溝の斜面と考えられる所（溝底の暗い線の片側に続く、暗さがしきい値すれすれの行）が、溝底区間に入って溝底として検出された**ことによる。plan.md 2.3 の考察にあった「溝と溝の間の平らな所」は正しくない。
- 写真5の4本目 x=1141〜1159 は、レコード針が溝の斜面の一部を削り、溝底が部分的に広くなったものが、影として写ったとユーザーは考えている。溝の本当の形として見るべきではない（plan.md 8章 Q7 の (3)）。
  - 暗さの分布でも、この所は暗い所そのものが広い。暗さ 0.7 以上の行が3〜4行（y=217〜220）あり、前後の列では1行だった（付録 B.2）。

### 2.3 スクリプトの値を変えるだけで、1回目の計画の値になる

- `findGrooveBottomIntervals` は、幅が上限以下の区間を、順番を変えずに残すだけである。そのため、上限を4にして検出した点は、上限8の点から幅5以上の点を除いたものと、順番も含めて同じになる。
- スクリプトと同じ流れ（`GroovePointCloud` → `mergeSegmentPoints` → `trackGroove`／`extractMultiGroove` → `detrendTrackedShape`）を `WIDTH_THRESH = 4` でやり直した。デトレンド前の y と点を採れた列は、1回目に幅つきの検出で求めたものと `isequal` で一致した。plan.md 7.3 の値（\|振幅\| > 0.8 が 1・9・9、\|振幅\| > 1 が 0・0・0、変わった列が 7・106・106 で、そのうち幅4以下の点の列は0）がすべて出た（付録 B.4）。
- 1104 hist のヒストグラムの山の中心は、8枚×5本とも変わらなかった。`trackGroove:longGap` などの警告も出なかった。直した後の 1104 hist と track5 は、y も点を採れた列も同じになった。

### 2.4 続いた外れ値を数える指標

**問題**：21列の窓の局所的なずれでは、11列以上続く外れ値を数えられない。窓の中央値も一緒に動くからである。写真5の4本目 x=1141〜1159（19列。うち17列が幅5）では、局所的なずれは 0 付近だった。

**分かったこと**（候補と数値は付録 B.3 の表）

- この所の重心は、溝底の線の芯より 0.45 px 下にある。この大きさは、正常な点にも出る差と同じである。区間が数行しかなく、暗さが8ビットなので、試したどの求め方でも、芯の位置には行の量子化による 0.45〜0.5 px の差が正常な点で出た。そのため、1列ずつのしきい値では分けられなかった。
- 経路の形（約20列で約 1.4 px のふくらみ）も、音の成分と同じ長さと大きさである。経路だけを使う指標（中央を除いた広い窓、61列の窓）は、続いた外れ値を数えるほど広げると、幅4以下の点を数百点数えた。
- \|振幅\| > 1 は、このデータでは幅4以下の点を1点も数えず、続いた外れ値の17列を数えた。しかし、この所の振幅が1を超えたのは、ずれ（振幅で約 0.3）が、音の振幅の大きい所（約 0.7）に重なったからにすぎない。音の小さい所で同じずれが起きれば数えられないので、指標にはしない（参考として数える）。
- 放物線の頂点との差を使い、同じ向きのずれが続くことを条件にすると、続いた外れ値と正常な点を分けられた。

**採る指標：芯からのずれが続く区間**（定義は 7.2 の (b)）

1. **芯の位置**を、写真の暗さから列ごとに求める。出力の y を丸めた行の上下2行（合わせて5行）のうち、最も暗い行を選ぶ。その行と上下の行の3点に放物線を当てはめ、頂点の y を芯の位置とする。しきい値と溝底区間を使わないので、肩の行（しきい値すれすれの行）に左右されない。
2. **芯からのずれ**を、出力のデトレンド前の y − 芯の位置 とする。点を採れずに補間した列でも求められるので、直した後に補間に置き換わった列も、同じ物差しで測れる。
3. 同じ溝・写真の中で、芯からのずれが同じ向きに **0.35 px 以上**の列が **10列以上**続く区間を、**続いた外れ値**とする。

## 4. 設計

### 4.1 処理の流れ

自動追跡の3つのスクリプトの処理の流れは変えない。区間ごとの溝底点の検出で使う幅の上限だけが変わる。

1. 区間（セグメント。写真1枚を横に10等分したもの）の画像から `DarknessMap` を作り、`setDiffTF(D_THRESH)` でしきい値を超える所を求める（今と同じ）。
2. 列ごとに `GrooveExtractor` の `findThresholdIntervals` → `findGrooveBottomIntervals(…, WIDTH_THRESH)` → `extractByCentroid`・`extractByLocalMax` を呼び、溝底点を求める（今と同じループ）。**`WIDTH_THRESH` が 4 になるので、幅5以上の区間は溝底点にならない。**
3. 以降（`mergeSegmentPoints` → `trackGroove`／`extractMultiGroove` → `detrendTrackedShape` → 保存）は今と同じ。cycleResult の `conditions.wTh` には 4 が入る。

重心法と局所的最大値法の両方に、同じ幅の上限を使う（Q6 の決定）。従来法のスクリプト（`pkCentroid_1cycle.m` など）は変えない（Q5 の決定）。

### 4.2 スクリプトの変更

3つのスクリプトとも、同じように変える。

1. パラメータの行を、次のようにする。行末のコメントの「（pkCentroid_1cycle.m と同じ）」は、値が違うようになるので消す。

### 7.2 外れ値の定義と、数える量（criteria.md の素案）

**外れ値の定義**（重心法。1つのデータ・溝（周）・写真ごとに、デトレンド前の y（元の画像の px）を使う）

- **(a) 短い外れ値**（Q1 の決定）：点を採れた列で、局所的なずれ（前後21列で点を採れた列の y の中央値との差）の絶対値が **1 px** を超えるもの。MATLAB では `yf = y; yf(~found) = NaN; dev = yf - movmedian(yf,21,"omitnan")`。窓としきい値の根拠は plan.md 7.2 の表。
- **(b) 続いた外れ値**（新しい指標。2.4、8章 Q9）：芯からのずれ（出力の y − 芯の位置）が、同じ向きに **0.35 px** 以上の列が **10列以上**続く区間。補間した列も含めて、すべての列で測る。
  - 芯の位置の求め方：写真の暗さ `Dp = 1 - double([imgs.img])/255` の列 x で、`round(y)` の行とその上下2行（合わせて5行）のうち、最も暗い行 m を選ぶ（同じ暗さが複数あれば、その中央に近い行）。m とその上下の行の暗さ a・b・c に放物線を当てはめ、頂点 `m + 0.5*(a - c)/(a - 2*b + c)` を芯の位置とする。放物線が山の形（上に凸）にならない（`a - 2*b + c >= 0`）ときは m にする。
  - 局所的最大値法には使わない（y が1行単位なので、0.5 px のずれが続きやすい）。
- **(c) 参考**：正規化した振幅（デトレンドした y から全体の平均を引き、`AMP_DIV` = 1.5 px で割ったもの）の絶対値が 0.8・1 を超えるサンプル。音の大きさとデトレンドに左右されるので、判定には使わない。

**数える量**（直す前と後で表にする）

- (1) 外れ値の数と場所の一覧
  - (a) の短い外れ値：データ、溝の選び方、周、写真、x、幅、局所的なずれ、振幅
  - (b) の続いた外れ値：区間ごとに、データ、周、写真、x の始めと終わり、列の数、幅5以上の点の列の数、変わった列の数、芯からのずれの平均
- (2) \|振幅\| > 0.8・> 1 のサンプルの数と場所（参考）
- (3) **原因の量**：選んだ点のうち幅5以上の点の数と、その点が続く区間（2列以下のすき間はつなぐ）。直す前は、写真5の4本目 x=1141〜1159 などを数える。直した後は定義上0になるので、計画どおりかの確認にだけ使う。
- (4) **変わった列**：デトレンド前の y の差が 1e-9 を超える列の数。直す前のその列を、次の3つに分けて数える。
  - (i) 幅5以上の点を採っていた列（除いた列）
  - (ii) 点を採れずに補間していた列（隣の点が変わったので、補間の値が変わる）

## 9. リスク

- **本実装の欠点（ユーザーの指示で明記する）**：溝底区間が広く、かつ取り出した点が正しく溝底の上にあるときにも、その点を外れ値とみなして（溝底点にせず）、前後の列からの補間に置き換えてしまう場合がある。1104 では、幅5以上で外れ値でない78点が補間に置き換わった（y の変化の中央値 0.45 px）。ユーザーは、外れ値でない場所の点が変わることを受け入れた。「暗さがしきい値以上の範囲を溝底とする」というこの方法では、どうしても出てくる部分だからである。README の「溝の自動追跡（trackGroove）」の節にも書く。
- **写真5の4本目では、溝底の線そのものが下がった分は残る。** 案A は、重心が芯からずれた分（約 0.45 px）を除くだけで、芯そのものが約 1 px 下がっている分（x=1138〜1160）は直した後も出力に残る（x=1138〜1160 の振幅は、直す前の最大 1.23 から、直した後は 0.35〜0.78 になる）。ユーザーはこの所を溝の本当の形と見ていないが、写真の暗さだけからこの下がりを見分ける方法は、この計画では見つけていない。U2 で見てもらう。
- **ほかのレコード・ほかの撮影条件では、溝底の線そのものが幅5以上になることがある。** そのときは、幅の上限4で溝底点が大量に消え、`trackGroove:longGap` の警告が出る（警告で気づける）。代わりの案は、幅の上限を上げるか、案D（幅の広い区間で重心を計算し直す）である。

```matlab
% 芯の位置（出力の y のまわり ±2 行で最も暗い行と、その上下の行の3点の放物線の頂点）。
% yB は直す前、yA は直した後（幅5以上の点を除いて線形補間。B.4 でスクリプトの流れと一致を確かめた）
for nm = names
    T = D.(nm); n = height(T); fA = T.found & ~(T.w >= 5); yA = NaN(n,1);
    keys = unique([T.groove T.photo],'rows','stable');
    for q = 1:size(keys,1)
        idx = find(T.groove==keys(q,1) & T.photo==keys(q,2));
        y = T.y(idx); y(~fA(idx)) = NaN; yA(idx) = fillmissing(y,"linear");
    end
    cB = NaN(n,1); cA = NaN(n,1);
    for k = 1:n
        Dp = Dph{T.photo(k)}; H = size(Dp,1); x = T.x(k);
        for pass = 1:2
            if pass == 1, yy = T.y(k); else, yy = yA(k); end
            r0 = round(yy); rr = (max(2,r0-2):min(H-1,r0+2))';
            d = Dp(rr,x); tie = rr(d == max(d)); [~,kk] = min(abs(tie - mean(tie))); m = tie(kk);
            a = Dp(m-1,x); b = Dp(m,x); c = Dp(m+1,x); den = a - 2*b + c;
            if den >= 0, v = m; else, v = m + 0.5*(a - c)/den; end
            if pass == 1, cB(k) = v; else, cA(k) = v; end
        end
    end
    T.yAfter = yA; T.foundAfter = fA; T.coreB = cB; T.coreA = cA; D.(nm) = T;
end
% 続いた外れ値の区間：同じ溝・写真の中で、同じ向きに |e| >= TE の列が L 列以上続く
TE = 0.35; L = 10;
for nm = names
    T = D.(nm); keys = unique([T.groove T.photo],'rows','stable');
    for ph = ["before","after"]
        if ph == "before", e = T.y - T.coreB; else, e = T.yAfter - T.coreA; end
        runs = [];
        for q = 1:size(keys,1)
            idx = find(T.groove==keys(q,1) & T.photo==keys(q,2));
            for sg = [1 -1]
                hit = sg*e(idx) >= TE;
                dl = diff([0; hit; 0]); st = find(dl == 1); en = find(dl == -1) - 1;
                for r = find(en - st + 1 >= L)'
                    runs = [runs; keys(q,:) T.x(idx(st(r))) T.x(idx(en(r))) en(r)-st(r)+1]; %#ok<AGROW>
                end
            end
        end
        fprintf("%s %s: %d 区間\n", nm, ph, size(runs,1)); disp(runs)   % [溝 写真 x始め x終わり 列の数]
    end
end
```
