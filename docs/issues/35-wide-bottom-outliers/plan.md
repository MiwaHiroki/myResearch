# #35 正規化した振幅が1付近の外れ値が、溝の選び方によらず出る — 計画

## 1. 結論

- **外れ値は、溝底点の検出の段階で生じる。** 溝底の暗い線のすぐ隣に、暗さがしきい値（`D_THRESH` = 0.6）すれすれの薄暗い所があると、溝底区間（暗さがしきい値以上の連続した行）がそこまでつながって広がる（幅5〜8 px）。区間の重心は、広がった側へ、1行あたり約 0.45 px ずれる。そのため、幅5以上の点は溝底の線から 1〜2 px ずれる。溝の選び方（自動追跡・帯・従来法）は、どれもずれの許容範囲（2〜3 px）が広いので、この点を採る。写真に重ねた図でも、ずれた点は溝底の暗い線の端（薄暗い所との境目）にあった（2.3）。
- **推奨は案A：自動追跡の3つのスクリプトで、溝底区間の幅の上限 `WIDTH_THRESH` を 8 から 4 に下げ、幅5以上の区間を溝底点にしない。** 3つのスクリプトに同じ形で書かれている溝底点の検出の処理を、新しい関数 `src/detectGroovePoints.m` にまとめ、幅の上限の既定値を4にする。従来法のスクリプト（`pkCentroid_1cycle.m` など）と `GrooveExtractor` は変えない。
- **実データで試した結果、外れ値（局所的なずれが 1 px を超える点）は、1104 hist で 26 → 0、1104 track で 25 → 0、1014 track で 1 → 0 になった。** 正規化した振幅の絶対値が1を超えるサンプルも、32・31・1 → 0 になった。y が変わった列は、幅5以上の点を採っていた列と、その隣で補間していた列だけだった。幅4以下の点を採っていた列は、1列も変わらない。ヒストグラムの山の中心も変わらない。
- **代わりに、幅5以上で外れ値ではなかった点（1104 で78点）も、前後の列からの補間に置き換わる**（y の変化の中央値 0.45 px）。その多くも、同じ仕組みで 0.45〜0.95 px ずれていた点である。
- 外れ値の定義（Q1）は、「その列の溝底点の y と、前後21列で点を採れた列の y の中央値との差（局所的なずれ）が 1 px を超える点」を推奨する。未決事項は6つ（8章）。

> - ただし、`src/detectGroovePoints.m` は作らない。ユーザーは、リファクタリングを別の機会にまとめて行う。そのため、今回は過去のスクリプトを愚直に参考にし、本実装と直接関係のない共通関数を作らない。スクリプトの末尾にローカル関数を作るのはよい。3つのスクリプトは、検出のループを今のまま残し、`WIDTH_THRESH` の値だけを 8 から 4 に変える。

2. **ずれの仕組み：溝底の線が、隣の薄暗い所とつながる。** 715 ms の外れ（写真8、x=1862・1865）で、列ごとの暗さの分布を見た（図 `temp/35-plan/profile_1104_groove1_img8_x1861-1862-1865.png`）。
   - 溝底の暗い線は y=286〜287 にあり、暗さは約 0.73。その下の y=289〜291 に、暗さが 0.58〜0.62 の薄暗い所がある。
   - 隣の列（x=1861）では、y=289・290 の暗さが 0.596・0.588 としきい値をわずかに下回るので、区間は 285〜288（幅3）で終わり、重心は 286.53 になる。
   - x=1862 では、y=289〜291 の暗さが 0.608・0.605・0.620 としきい値をわずかに上回るので、区間が 285〜291（幅6）までつながり、重心は 287.92（+1.4 px）になる。x=1865 も同じで、幅5、重心は 288.39 になる。
   - 重心は暗さで重み付けした平均なので、しきい値すれすれの行も、溝底の行とほぼ同じ重みで効く。1行広がるごとに、重心は約 0.45 px ずれる。局所的なずれの値は、ほぼ 0.45 px の整数倍（0.44・0.9・1.35・1.85）に並んでいた。
   - 区間が上下の両側に同じだけ広がったとき（写真8の x=33〜36 など）は、重心はずれない。幅5以上で外れ値ではない点の多くは、これにあたる。
3. **溝の選択：外れ値を作らないが、通してしまう。** 幅5以上の点を検出の段階で除いて、溝の選択をやり直した（案A）。1104 hist では、ヒストグラムの山の中心（`centersCnt`・`centersMax`）は8枚×5本とも変わらず、選んだ点も、除いた点を除けばすべて同じだった（`trackGroove` で追跡した1本目、帯で取り出した2〜5本目とも）。溝の選択は外れ値の原因ではなく、許容範囲（追跡の `Tolerance` = 2 px、帯の ±3 px）が外れ値のずれより広いので、そのまま通している。
4. **デトレンド：原因ではない。** 局所的なずれはデトレンドの前の y で測っており、デトレンドに関係なく外れ値が見つかる。幅5以上の点を除いても、y が変わらない列の振幅の変化は、写真ごとの9次の多項式が少し変わる分だけ（最大 0.025）だった。
5. **局所的最大値法は、幅の広い区間でもずれない。** 区間の中で最も暗い行を選ぶので、薄暗い所がつながっても、溝底の線の上に残る。1104 hist（局所的最大値法）で、幅5以上の104点のうち局所的なずれが 1 px 以上の点は1点だけ、|振幅| > 1 は0点だった。局所的最大値法の |振幅| > 0.8 の112点は、y が1行単位でしか変わらないことによる跳び（幅1〜3の点）だった。
6. **幅4以下の点も、区間がまるごと1行ずれると、0.9 px 跳ぶ。** 幅4以下で局所的なずれが 0.75 px を超える点が193点あった（1104 hist）。多くは、区間の始めと終わりが前後の列と比べて同じ向きに1行ずれた点で、しきい値で区間を切る同じ仕組みによる。ただし、1 px は超えない（最大 0.967 px）。このissueの外れ値（1 px を超える跳び）とは分け、続きのissueの候補にする（3章の案E、9章）。
7. **溝と溝の間の、幅の広い区間。** 8枚の写真のすべての溝底区間（幅8以下、578,114個）の幅の分布は、幅0〜8の順に 2,419・125,554・344,294・89,626・5,388・282・181・370・10,000 個だった。幅5〜6が谷になる。幅の上限を4にすると、10,833個（1.9%）の区間が溝底点でなくなる。そのうち10,000個は幅8の区間で、ほとんどは溝と溝の間にある（`results/1111/README.md`。`ad46b44` で境界値を含めるようにしてから増えた点）。溝の選択では、もともとほぼ使われていない。

## 4. 設計

### 4.1 処理の流れ

### 4.2 インターフェース

```matlab
function [ptsCnt, ptsMax, widths] = detectGroovePoints(map, opts)
% 区間の暗さ（setDiffTF 済みの DarknessMap）から、各列の溝底点を重心法と局所的最大値法で求め、
% GroovePointCloud にして返す。幅（最後の行 − 最初の行）が WidthThresh を超える区間は溝底としない。
% 溝底の線がしきい値すれすれの隣の薄暗い所とつながって区間が広がると、重心が 1〜2 px ずれ、
% 音声の外れ値になるため（issue #35）。自動追跡のスクリプトが共通に使う。
    arguments
        map (1,1) DarknessMap                                   % setDiffTF を済ませたもの
        opts.WidthThresh (1,1) double {mustBeNonnegative} = 4   % 溝底区間の幅の上限 [px]（元の画像のpx）
    end
```

- 戻り値
  - `ptsCnt`・`ptsMax`：`GroovePointCloud(map)`。`peakCells{x}` は `[x*ones(n,1), y]`（n はその列の溝底点の数。0なら 0×2）。今のスクリプトの `pts_cnt`・`pts_max` と同じ形。
  - `widths`：(1, `map.nCols`) の cell。`widths{x}` は (n,1) の溝底区間の幅 [px]（元の画像の px。`(btmLastIdx - btmFirstIdx) / map.scaleFactor.row`）。行の順は `peakCells{x}` と同じ。評価や図で、点の幅を調べるために使う。
- エラー
  - `detectGroovePoints:diffTFNotSet`：`map.diffTF` が空（`setDiffTF` を呼んでいない）。
  - `detectGroovePoints:columnsChanged`：`map.nCols ~= map.width`（`dInterp` で列を増やした map）。`GroovePointCloud.peakCells` の長さが元の幅なので、列を増やした map は扱わない。`dResample` は行だけを増やすので扱える。
- 使用例（スクリプト。区間ごとのループの中）

```matlab
origD = DarknessMap(origImg);
origD = origD.setDiffTF(D_THRESH);
[pts_cnt, pts_max] = detectGroovePoints(origD, WidthThresh=WIDTH_THRESH);
allImg(kImgSmall) = origImg;
allPts_cnt(kImgSmall) = pts_cnt;
allPts_max(kImgSmall) = pts_max;
```

- スクリプトの冒頭のパラメータは、次のようにする（3つとも同じ）。

```matlab
WIDTH_THRESH = 4;   % 溝底区間の幅の上限[px]。これより広い区間は、溝底の線が隣の薄暗い所とつながったもので、
                    % 重心が1〜2 px ずれるので溝底としない（issue #35。従来法の pkCentroid_1cycle.m は 8 のまま）
```

### 7.2 外れ値の定義と、数える量（criteria.md の素案）

**外れ値（列ごとの指標）**

1. 1つのデータ・抽出法・溝（周）・写真ごとに、デトレンド前の y（元の画像の px。`yAbs*`）と、点を採れた列（`found*`）を使う。
2. 各列の**局所的なずれ**を、その列の y から、前後10列（合わせて21列）のうち点を採れた列の y の中央値を引いた値とする（MATLAB では `yf = y; yf(~found) = NaN; dev = yf - movmedian(yf,21,"omitnan")`）。
3. 点を採れた列で、局所的なずれの絶対値が **1 px** を超えるものを外れ値とする。

窓を21列にする理由：窓の長さを変えて、幅4以下の点のずれの最大と、外れ値の数を比べた（1104 hist、重心法）。

| 窓 [列] | 幅4以下の点のずれの最大 [px] | 幅4以下の点で 1 px を超えるもの | 幅5以上の点で 1 px を超えるもの |
|---|---|---|---|
| 11 | 0.967 | 0 | 20 |
| **21** | **0.967** | **0** | **26** |
| 41 | 0.979 | 0 | 26 |
| 61 | 1.463 | 40 | 31 |
| 101 | 1.967 | 414 | 31 |

- 11列では、5列ほど続いた外れ（写真8の5本目 x=2089〜2093）を中央値が追いかけ、見逃す。
- 61列以上では、音そのもの（ゆっくりした揺れ）がずれに入り、幅4以下の点も 1 px を超える。
- 21列（約 0.5 ms）は、すべての外れ値を数え、幅4以下の点を数えない、最も短い窓。issue の定義とも同じ。
- しきい値 1 px（正規化した振幅で 0.67）：21列の窓では、幅4以下の点のずれは 1 px を超えない（2.2の1）。
- 限界：11列以上続く外れ（写真5の4本目の17列）は、中央値も一緒に動くので数えられない。そのため、下の「幅5以上の選んだ点の数」と |振幅| も数え、図でユーザーが確かめる。

- **ほかのレコード・ほかの撮影条件では、溝底の線そのものが幅5以上になることがある。** そのときは、幅の上限4で溝底の点が大量に消え、`trackGroove:longGap` の警告が出る（警告で気づける）。代わりの案：幅の上限を上げるか、案D（幅の広い区間で重心を計算し直す）を `detectGroovePoints` の選択肢として足す。
- **連続した幅の広い点（写真5の4本目）では、溝の本当の形を少しならす。** 1104 では1か所だけだった。ユーザーの目視（Q7）で問題になれば、案Dに切り替える。
- **幅4以下の点の 0.9 px の跳び（2.2の6）は残る。** このissueの外れ値（1 px 超）ではないが、|振幅| > 0.8 の残り9点の多くはこれにあたる。続きのissueの候補：重心の重みを「暗さ − しきい値」にする（案E。試行では、幅4以下でずれ > 0.75 px の点が 193 → 0）。重心法の定義が変わるので、従来法との比べ方を含めて別に計画する。
- **高解像度化（`rsmplD`・`intpD`）では、幅の分布を確かめていない。** `findGrooveBottomIntervals` は幅の上限に `scaleFactor.row` を掛けるので、上限4は元の画像の 4 px を意味する。補間で暗さの分布がなめらかになったり波打ったりすると、区間の広がり方が変わる（合成データでも、リサンプルの波打ちで、暗さ 0.62 の薄暗い所が溝から切り離された。付録 A.9）。高解像度化のissueで確かめる。`detectGroovePoints` は `dInterp` の map を扱わない（エラーにする）。
- **実験をやり直した後の比較。** 新しい自動追跡のデータ（幅の上限4）と、過去の従来法のデータ（8）は、溝底点の数が違う。溝底点の一致を前提にしたスクリプト（`grooveOnImageManualAndTrack.m`）は止まるので、やり直すとき（Q4）に、比べ方を決め直す。

> **ユーザーの回答（2026-11-14）**
> - **本実装の欠点として明記する**（8章 Q7 の (2)）：溝底範囲が広く、かつ取り出した点が正しく溝底の上にあるときにも、その点を外れ値とみなして（溝底点にせず）補間に置き換えてしまう場合がある。ユーザーは、外れ値でない場所の点が変わることを受け入れた。「暗さがあるしきい値以上の範囲を溝底とする」というこの方法では、どうしても出てくる部分であるため（7.4 の回答）。
> - **案E（重心の重みを「暗さ − しきい値」にする）は、このissueの最後まで残す。** ユーザーは、効果がありそうだと考えており、あとで詳しく検討したい。issue に追加することを検討している（3章の回答）。
