# #35 から続くissueの案

issue #35（正規化した振幅が1付近の外れ値が、溝の選び方によらず出る）の作業中に出た、続きの作業の案。issueのひな型（`.github/ISSUE_TEMPLATE/`）に沿って書き起こすときの材料にする。

## 言葉

- **溝底区間**：写真の各列で、暗さ（1 − 画素値/255）がしきい値 `D_THRESH`（0.6）以上の行が続く範囲。**幅**は、その最後の行 − 最初の行 [px]。
- **芯の位置**：溝底点のまわりで最も暗い行と、その上下の行に当てはめた放物線の頂点。溝底の暗い線の中心の目安にする。
- **芯からのずれ**：出力の y（デトレンドの前）− 芯の位置 [px]。

## 案A：重心の重みを「暗さ − しきい値」にする（plan-2.md の案E）

- ラベル: `feature`
- ゴール: 重心法で、各行の重みを暗さそのものではなく「暗さ − しきい値」にする。しきい値すれすれの薄暗い行が、重心を引っぱる影響を小さくする。
- 背景
  - #35 では、幅5以上の区間を溝底点にしないことで外れ値を除いた。幅4以下の区間でも、しきい値すれすれの行が片側だけ入ると重心がずれる。写真2の4本目 x=1883〜1892 では、0.4 px のずれが10列続いていた（plan-2.md 2.4）。このずれは #35 の後も残っている。
  - plan-2.md の試行（付録 B.7）では、幅を絞らなくても、続いた外れ値の区間が0になった。変わらなかった幅4以下の列の芯からのずれの平均は、0.150 → 0.047 px になった。ただし、芯の位置も最も暗い行を重く見る推定なので、この指標は案A に有利に出る。
  - ユーザーは効果がありそうだと考えており、issue に追加することを検討している（2026-11-14）。
- 未決事項の候補
  - 変える所：重心は `GrooveExtractor.extractByCentroid` で求めるので、そのまま変えると従来法（`pkCentroid_1cycle.m` など）の出力も変わる。自動追跡のスクリプトだけに効かせるかを決める。
  - 幅の上限：#35 の 4 のままにするか、案A と組み合わせて上げるか。上げれば、#35 の欠点（幅が広くても点が正しく溝底の上にあるときに、補間に置き換えてしまう）が減るかもしれない。
  - 評価：芯からのずれは案A に有利に出るので、別の確かめ方（局所的最大値法の点との差、写真に重ねた図）を合わせる。
- 作るタイミング: #35 のPRがマージされた後。

## 案C：高解像度化した画像での、幅の上限の確かめ

- ラベル: `feature`（単独のissueにせず、高解像度化のissueに含める）
- ゴール: `dResample`・`dInterp` で高解像度化した画像でも、幅の上限4が同じように働くかを確かめる。
- 背景: `findGrooveBottomIntervals` は幅の上限に `scaleFactor.row` を掛けるので、上限4は元の画像の 4 px を意味する。補間で暗さの分布がなめらかになったり波打ったりすると、区間の広がり方が変わる（plan-2.md 9章）。#35 は高解像度化なし（`origD`）だけを扱った。
- 扱い: 自動追跡の高解像度化（#25・#30 の [`follow-ups.md`](../closed/30-multi-groove/follow-ups.md) の案B。まだissueになっていない）を作るときに、確かめることの1つとして入れる。
- 作るタイミング: 高解像度化のissueを作るとき。
