# 文章の書き方

Claude（メインセッション・サブエージェントとも）が、人が読む文章を書くときのルール。対象は、リポジトリに残す文書（`docs/`、受け渡しファイル、`README.md`、issue・PR の本文、コミットメッセージの本文）と、ユーザーへの報告。

ほかに決まりがあるものは、それにも従う（報告の項目は [`communication.md`](communication.md)、図の文字は [`figures.md`](figures.md)、issue の「解決のまとめ」は `.claude/agents/summarizer.md`）。このファイルは `CLAUDE.md` から毎回読み込まれるので、短く保つ。

## 全体

- 結論を先に書き、根拠や詳細は後に書く。
- 読み手は、その作業の会話を知らない人とする。会話や受け渡しファイルを読まなくても、一度読んで分かるように書く。
- 文章で書けることは文章で書く。コード（関数の呼び出し方の例など）は、文章では伝わらないもの（ファイル名の決まりなど）に限る。

## 文

- **変数名・引数名で説明しない。** まず意味を言葉で書き、名前は添えるだけにする。条件や数値も、何のための値なのかを書く。
  - 悪い例：「始点の列から右へ `InitLength` 未満の列で、クリックのyから `SnapRadius` 以内にある最も近い点の中央値を始点のyにする。」
  - よい例：「クリックした位置は少しずれていることがあるので、追跡を始める前に、始点の高さを決め直す。始点から右の一定の範囲（`InitLength`）の各列で、クリックした高さに最も近い溝底点を1つずつ選び、その高さの中央値を始点の高さにする。」
- **述語のある文で書く。** 「〇〇：△△」の形で名詞を並べただけの、文になっていない書き方をしない。
  - 悪い例：「実行するもの：`Research.prj` を開いて `scripts/grooveTrack_1cycle.m`」
  - よい例：「MATLAB で `Research.prj` を開き、`scripts/grooveTrack_1cycle.m` を実行する。」
- **1文に1つのことを書く。** 「〜し、〜して、〜なので、〜する」と続く長い文は、分ける。
- **専門用語・略語・新しい記号は、初めて出たところで意味を書く。** このプロジェクトの言葉（セグメント、`origD`、cycleResult、重心法・局所的最大値法 など）も同じ。
- **手順には、何のために行うのかを添える。**
- 書き終えたら読み直し、会話を知らない人が一度で意味を取れない文は書き直す。

## 番号

- **手順、プログラムの実行の順、処理の順は、番号付きの箇条書き（`1.` `2.` …）で書く。**
- 1つの手順の中の、さらに細かい順番は **(1)(2)…** で書き、字下げする。
- 場合分け（「〜のときは」「〜のときは」）と、選ぶ候補（質問の選択肢など）は **(a)(b)…** で書く。順番には使わない。
- 順序の無い項目の並び（採らなかった案、制約など）は、番号を付けず `-` の箇条書きにする。
- 例：
  ```markdown
  3. 追跡の始点を決める。
     - (a) 前の結果を使わないときは、画像を表示し、ユーザーが溝を1回クリックする。
     - (b) 前の結果の .mat を指定したときは、そこから始点を読む。
  4. `trackGroove` で溝を追跡する。
     - (1) 点群を列ごとに分ける。
     - (2) 始点の高さを決め直す。
     - (3) 始点の列から右端まで、1列ずつ進む。
  ```

## 箇条書きのまとめ方

- **同じ種類の項目を、1つの見出しの項目の下にまとめて階層にする。** 同じ階層に、種類の違う内容を並べない。
- 見出しの項目には、何の集まりかが分かる名前を付ける（「判定の補足」「ユーザーの確認」「参考（判定には使わない）」「制約」など）。その下に、中身を字下げして並べる。
- 悪い例（判定の補足・テスト・ユーザーの確認が同じ階層に並ぶ）：
  ```markdown
  - 一致しなかったセグメントは、手動側が端の点を落とした所である。
  - `runAllTests` は148件すべて通過した。
  - ユーザーは次の4つを確認し、問題なしとした。
  ```
- よい例：
  ```markdown
  - 判定の補足
    - 一致しなかったセグメントは、手動側が端の点を落とした所である。
  - ほかの確認
    - `runAllTests` は148件すべて通過した。
  - ユーザーの確認：次の4つを見て、問題なしとした。
    - 追跡の経路を写真に重ねた図
  ```

## このルールの育て方

- ユーザーから文章の書き方を指摘されたら、Claude がこのファイルに1項目足す（できれば悪い例・よい例を付ける）。特定の文書だけに関わることは、その文書の定義やひな型に書く（「解決のまとめ」なら `.claude/agents/summarizer.md`）。
- 足したことは、報告に書く。変更は `master` にコミットする（[`../git-rules.md`](../git-rules.md)）。作業ブランチにいるときは、自分では変えずに、ユーザーにそのことを伝える。
- 80行を超えそうなら、似た項目をまとめて短くする。
