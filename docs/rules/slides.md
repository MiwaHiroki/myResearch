# 進捗報告のスライド

Claude（メインセッション・サブエージェントとも）が、進捗報告のスライドを Typst で作るときのルール。作業の流れ、フォルダの構成、分担、Typst の書き方は [`../progress-slides.md`](../progress-slides.md) に、Claude の手順は skill `make-progress-slides`（[`.claude/skills/make-progress-slides/SKILL.md`](../../.claude/skills/make-progress-slides/SKILL.md)）に書いてある。

見た目（大きさ・色・間隔）は、テンプレート [`slides/template/progress.typ`](../../slides/template/progress.typ) がすべて決める。テンプレートの値は、ユーザーが Google Slides で使っていた自作テンプレートを実測して合わせたものである。そのため、`.typ` の中で文字の大きさや行の間隔を直接変えない。変えたいときは、ユーザーに確かめてからテンプレートを直す。

## 進捗報告の目的

進捗報告は、成果を見せるためだけの場ではない。ユーザーが今考えていることを指導教員に伝え、指導教員とともにその内容を考察し、研究の方向を決めるための場である。そのため、スライドでは、実装の現状・限界・不明点を含めた考察を明らかにする。見栄えの良い成果発表を目指してはならない。

具体的には、次のことを守る。

- うまくいかなかった結果、外れ値、限界を省かない。
- うまくいかなかった部分があれば、その部分を詳しく説明し、原因を徹底的に調べる。
  - 原因は、進捗ログ、issue の受け渡しファイル（`docs/issues/`）、コード、結果のデータまでさかのぼって調べる。
  - 調べても原因が分からなければ、分かったこと、考えられる原因、それを確かめる方法を書く。
- うまくいかなかった部分を説明する図は、ユーザーが `results/figures/progress/` に置いている。その図で説明が足りるかを吟味する。足りなければ、どんな図が要るか（何を示すための図か）を、報告でユーザーに提案する。
- 不明点は「？」で示し、「検討事項」にまとめる。
- 図を選ぶとき、うまくいった部分だけを選ばない。
- 推測と事実を区別する（書き方は「文言」の節）。

## スライドの種類

ユーザーが Google Slides で使っていた4つのレイアウトに、テンプレートの関数が対応する。これ以外のレイアウトは作らない。

| レイアウト | 関数 | 使う所 |
|---|---|---|
| タイトルスライド | `title-slide(date: "YYYY/MM/DD")` | 1枚目だけ |
| タイトルと本文 | `slide(title: [...])[本文]` | ふつうのスライド |
| タイトルのみ | `slide(title: [...])[図だけ]` | 本文の文を書かず、図だけを置くスライド |
| 白紙 | `blank-slide[...]` | タイトルの無いスライド |

- タイトルの後ろに細い字で添える文字（「(1周分)」「（参考）」「(11/12追記)」など）は、`title-note:` に書く。
- 最後の1枚は、次回までの ToDo を書くスライドにする。タイトルは「今回の日付 → 次回の日付」（例：`11/17 → MM/DD`）で、次回の報告日が未定なら `MM/DD` と書く。報告の時点では、中身を空の箇条書きにしておく。打ち合わせの後に、ユーザーが ToDo を書く（Claude に頼まれたら Claude が書く）。
- 2枚目は、前回のスライドの最後の1枚（ToDo）をコピーしたものにする。前回からの進捗を、このスライドで示すためである。
  - タイトルの `MM/DD` を、今回の報告日にする（例：`11/03 → 11/17`）。
  - 項目は、進み具合で分ける（11/17 の回では「完了」と「未着手」に分けた）。Claude は進捗ログをもとに下書きし、ユーザーが確かめる。
  - 右上の「MM/DDのスライド」の表示は付けない。
- 今回の報告日が未定の間は、スライドの中の今回の日付も `MM/DD` と書く。日付が決まったら直す（手順は skill `make-progress-slides`）。

## 説明の順

2枚目（前回の ToDo）と最後の1枚（次回までの ToDo）の間には、実装した内容を、次の順で説明する。

1. 実装内容の説明
2. 結果
3. 結果の考察
4. 検討事項・今後の方針
5. 補足・参考事項

- 複数の実装を行った回は、実装ごとに、この順の説明を繰り返す。
- 実装が終わっていないものは、終わった所まで書く（例：結果がまだ出ていなければ、実装内容と今の状態まで）。
- 過去のスライドのコピーは、この流れの中で、話に要る所に入れる。

## 文言

参考スライドは、`slides/reference/` にある（Google Slides で作った 11/03・11/17 の回と、自作テンプレート）。文言は参考スライドを参考にするが、完全に再現しなくてよい。ただし、記号の使い方は、下の「記号」の表のとおり、参考スライドの用法に合わせる。

- **タイトル**は、名詞で終える。スライドの内容を、できるだけ具体的に、短く表す。
  - 悪い例：「結果」
  - よい例：「溝の自動追跡結果(1周分)」「溝底の中心から離れた点」
- **本文**は、箇条書きでも文章でもよい（スピーカーノートを作らない進捗報告のスライドだから）。文章で書くときは句点「。」を付け、箇条書きの短い句には付けない。
- **「〜したい」と書かず**、動詞の現在形で終える。
  - 悪い例：「→点の抽出方法を見直したい」
  - よい例：「→点の抽出方法を見直す」
- **推測と事実を区別する。** 推測は「〜と思われる」「〜と推測される」と書く。
- **図の上には、それぞれの図の説明を付ける**（「左：従来法で抽出された溝底点」など）。同じ図や、表示する範囲を変えただけの図を再び載せるときは、説明を省く。
- 図を指すときは、「左：」「右：」「上：」「下：」の形で書く。「↓」は使わない（「画像上に表示したもの↓」ではなく「下：画像上に表示したもの」）。

### 記号

| 記号 | 意味 | 例 |
|---|---|---|
| → | (1) 結果・結論、(2) 次にすること・方針、(3) 処理の順、(4) 期間 | 「→ほぼ正しく追跡できている」「→原因となった点を探る」「クリック→自動追跡→デトレンド」「11/03 → 11/17」 |
| ← | (1) 原因・理由、(2) 左の図を指す | 「←画像の切れ目での不連続が原因と思われる」「←丸をつけた位置付近にある点を」 |
| ※ | 注意・断り書き（例外や限界） | 「※画像上では ±1~2px のずれであり、」 |
| ？（全角） | まだ確かめていないこと、問い | 「照明の検討？」「この条件を今よりも厳しくする？」 |
| (?)（半角） | 1つの語の確からしさが低い | 「溝側面の傷(?)で」 |
| / | 「または」（どちらか一方か両方かは区別しない）。日付・分数・単位にも使う | 「結果が変わらなかった / 外れ値が余計に増えた」「1/8周」「[周/s]」 |
| = | 言い換え・同値、数式 | 「（=溝底範囲の推定）」「= 1/80周分」 |
| ～ ~ | 2つの物や数値の間の範囲。「A~B」「〇〇～△△」と書く。片方が自明か、省いても意味が伝わるときは、片方を省ける（「~2px」は「0~2px」、つまり2pxまで） | 「黄点～赤点の距離」「±1~2px」 |
| > | 階層（フォルダ・分類） | 「2025waseda > 写真 > 20261117」「電気音響 > 音響信号処理」 |
| ・ | 語を並べる（箇条書きの記号には使わない） | 「溝底範囲・重心の求め方」 |
| ,（半角） | 数を並べる | 「2, 3点」 |
| 「」 | 特別な意味で使う語 | 「ヒストグラムの「山」」 |
| [ ] | 単位 | 「[周/s]」 |
| (MM/DD) | 書いた日・書き足した日 | 「(10/6)照明の検討？」「(11/12追記)」 |

全角と半角は、次のように使い分ける。

- 括弧は、中身が数字で始まるときは半角「( )」、それ以外は全角「（ ）」にする（「(1周分)」「(11/12追記)」「（参考）」）。
- コロンは、日本語の語の後ろでは全角「：」にする（「左：」「セッション：」）。英字の語の後ろとファイル名の前では、半角「:」と空白にする（「README: 」「上: grooveHist_img2.png」）。
- 範囲の記号は、前後が数字・英字なら半角「~」、日本語の語なら全角「～」にする。

## 文字

- 本文は 20pt、箇条書きの2段目と補足の行は 16pt である。大きさは、テンプレートが決める。
- 本文の中の小見出し（「完了」「未着手」「実装案」など）は、`= 完了` のように見出しの書き方で書く。テンプレートが、太字の 24pt にする。文の中の一部を太くするとき（「*セッション*：」など）は、`*...*` で書く。
- 行の間隔は、テンプレートが決める。段落の中の行の送りは文字の大きさの1.32倍で、段落の間はそれより6pt広い。これは、Google Slides の「行間1.1、段落前6pt・段落後6pt」と同じ見た目である。
- 改行は、意味で2種類に書き分ける。
  - (a) 次の項・次の段落へ移るとき（Google Slides の Enter）は、新しい項（`-`）か、空行で区切った新しい段落にする。間が6pt空く。
  - (b) 項や段落の中で改行するとき（Google Slides の shift+Enter）は、行の末尾に `\` を書く。
- 箇条書きの記号は、1段目が「●」、2段目が「○」である。記号は、テンプレートが付ける。本文に「・」「●」を打ち込まない。
- 小さい字の補足（例：「（ギリギリ溝底と言える場所には位置している）」）は、`\` で改行した後に `#note[...]` で書く。
- 文字の背景を薄い赤で塗る強調は、`#hl[...]` で書く。
- 数式は Typst の書き方（`$D_"th"$` など）で書く。

## 図

- 載せる図は、報告のフォルダの `figures/` にコピーしてから使う。`results/figures/progress/` などを直接参照しない。報告で見せた図を残すためである（進捗報告用の図は、上書きして作り直すことがある）。
- 図は `fig-at` で、配置の型の範囲（`cell-left`・`cell-right`・`cell-full`・`cell-side`）に置く。スライドごとに図の位置がずれないようにするためである。型の範囲が合わないときだけ、範囲の上端（`top:`）を変える。それでも合わないときは、`fig-at` に座標を直接渡す。
- 図の下には、ファイル名（拡張子付き、フォルダ名なし）を、10pt の灰色で書く。`fig-at`・`fig` が自動で書くので、手で書かない。
- `image()` には `width`・`height` を付けない。大きさは `fig-at`・`fig` が決める。
- 図の中身を変えない。切り出し（`crop:`）はしてよい。明るさやコントラストは変えない（[`figures.md`](figures.md) の「撮影画像の表示」と同じ理由）。
- PowerPoint で作った図（アルゴリズムの説明図など）は、`slides/diagrams/` の PNG を `figures/` にコピーして使う。

## 強調の図形

- 図で説明したい所には、赤い丸・四角・線（`mark-oval`・`mark-rect`・`mark-line`）や、黒い矢印（`mark-arrow`）を付ける。これらの図形は、MATLAB で図を作るときには描かない。
- 図の上の図形は、`fig-at` の `marks:` に渡す。位置と大きさは、図に対する割合（0〜1）で書く。図の大きさや位置が変わっても、図形が図の同じ所に付いたままになるからである。
- 図と図の間の矢印や、スライドの上の文字・吹き出しは、`#draw(...)` で描く。座標はスライドの左上を原点とする pt で書く。
- 線の太さは、`thin`（0.75pt）・`medium`（1.5pt）・`thick`（3pt）から選ぶ。Google Slides の 1px・2px・4px にあたる。
- 図形の位置を Claude が決めたときは、PNG にして目視で確かめる。そのうえで、ユーザーに位置を直してもらう前提で、報告に「仮の位置」と書く。

## 過去のスライドのコピー

コピーするスライドは、ユーザーが決める。Claude は、自分の判断でコピーしない。

- (a) Typst で作った回のスライドは、`.typ` のソースごとコピーし、`slide(..., copied-from: "MM/DD")` にする。右上に赤字で「MM/DDのスライド」と書かれる。使っている図も、今回の `figures/` にコピーする。
- (b) Google Slides で作った回のスライドは、ユーザーが画像（PNG）か1ページの PDF を `copied/<MMDD>_p<ページ番号>.png`（または `.pdf`）に置く。`#copied-slide(image("copied/..."))` で載せると、右上の表示が自動で付く。

## スライドに載せないもの

作った音声と、ユーザーが操作する MATLAB の図（`.fig`）は、スライドに載せない。報告で見せるときは、報告のフォルダの `extras/` に入れる。論文の PDF は、ユーザーが自分で扱う。

## 確かめること

スライドを作ったり直したりしたら、次を確かめる。

1. コンパイルが、エラーも警告も無く通る。
2. ページ数が、作ったスライドの数と同じである。本文がスライドからはみ出すと、Typst は黙って次のページに送るためである。
3. すべてのページを PNG にして目視し、次の点を見る。
   - (1) 文字と図が重なっていない。
   - (2) 図の下のファイル名が読める。
   - (3) 強調の図形が、指したい所に付いている。

## このルールの育て方

ユーザーから、スライドのデザインや文言について指摘を受けたら、Claude がこのファイルに書き足す。文言の指針は、スライドを一緒に作りながら、ユーザーの説明を聞いて「文言」の節に足していく。足したことは報告に書き、`master` にコミットする（[`../git-rules.md`](../git-rules.md)）。
