# 質問・受け渡し・報告

Claude（メインセッション・サブエージェントとも）が、ユーザーへ質問し、作業を引き継ぎ、結果を報告するときのルール。

## 前提

サブエージェントは、ユーザーに直接質問できない。質問は、受け渡しファイルと最後の報告に「未決事項」として書く。メインセッションがそれをまとめて、ユーザーに尋ねる。

## 質問すべきこと

- 出力の数値（溝形状、音声など）が変わる変更
- issueの「未決事項」に挙がっていること
- `data/`・`experiments/` のファイルの作成・削除・上書き（[`data.md`](data.md)）
- 仕様の解釈が複数ありうること
- 既存の関数・クラスの動作を変えること

## 自分で決めてよいこと

ローカル変数の名前、内部での関数の分け方、テストケースの追加など、元に戻しやすく、出力が変わらないこと。決めた内容は報告に書く。

## 質問の形式

- 背景を1〜2文で書く。
- 選択肢を2〜4個示し、それぞれを選んだときの影響を書く。
- 推奨する案と、その理由を書く。
- 質問は1回にまとめて出す。小出しにしない。

## 止めるか、進めるか

- **止める**：質問すべきことのうち、後で直すと手戻りが大きいもの。決まるまで、その先の作業はしない。
- **進める**：それ以外は「仮定：〜」と明記して作業を続け、報告で目立つように書く。

## 受け渡しファイル

置き場所と運用は [`../issues/README.md`](../issues/README.md) に従う（`docs/issues/<番号>-<slug>/`）。

各ファイルの先頭に、次の項目を書く。

```markdown
- 段階: 計画 / 評価基準 / 実装 / 評価 など
- 作成者: <エージェント名 または main>
- 作成日: YYYY-MM-DD
- 入力: <読んだ受け渡しファイル、issue番号>
- 状態: 下書き / 承認済み
```

本文は結論を先に書き、根拠は後に書く。

## 最後の報告

作業の終わりに、次の項目を簡潔に報告する。

- 何をしたか
- 変更したファイル
- 検証の結果（テストの件数、`checkcode` の警告）
- 未決事項（質問の形式に従う）
- 仮定したこと
- 目視での確認が必要な残りの項目（実行できなかったことは、黙って省略しない）

長いログはそのまま貼らない。

## 言語

日本語で、簡潔に書く。
