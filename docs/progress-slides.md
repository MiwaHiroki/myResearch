# 進捗報告のスライド（Typst）

進捗報告は、成果を見せるためだけの場ではなく、今考えていることを指導教員に伝え、一緒に考察して研究の方向を決めるための場である（[`rules/slides.md`](rules/slides.md) の「進捗報告の目的」）。

進捗報告のスライドは Typst で書き、PDF にして Google Drive に上げる。Claude は、報告のフォルダ、スライドの下書き、PDF を用意する。ユーザーは、図と文言を直し、Drive にアップロードする。Google Drive と Claude は連携しない。

この文書には、フォルダの構成、作業の流れと分担、ユーザー向けの Typst の書き方、テンプレートの中身をまとめる。Claude が守るルールは [`rules/slides.md`](rules/slides.md) に、Claude の手順は skill `make-progress-slides` に書いてある。

## フォルダの構成

```
slides/
  template/progress.typ    テンプレート（見た目をすべて決める）
  diagrams/                PowerPoint で作った図（.pptx と、書き出した .png）
  reference/               参考スライド（Google Slides で作った 11/03・11/17 の回と、自作テンプレートの PDF）
  progress/<YYYY-MMDD>/    報告ごとのフォルダ（名前は報告日）
    <YYYYMMDD>.typ         スライドの本体
    <YYYYMMDD>.pdf         できあがったスライド
    figures/               スライドに載せる図のコピー
    copied/                過去のスライドの画像（ユーザーが置く）
    extras/                スライドに載せないが、報告で見せるもの（音声、.fig）
```

- `slides/` の下は、すべて git で管理する。他の PC と共有でき、`.typ` を直した履歴も残るためである。
- `figures/` には、`results/figures/progress/` などから図をコピーする。進捗報告用の図は上書きして作り直すことがあるので、コピーしておけば報告で見せた図が残る。
- `extras/` は、見せるものがある回だけ作る。
- 報告日が未定の間は、フォルダとファイルの名前の日付の所を、文字列 `MMDD` のままにする（例：`slides/progress/2026-MMDD/2026MMDD.typ`）。報告日が決まったら、Claude が名前とスライドの中の日付を直す。
- 例：2026/11/17 の報告は `slides/progress/2026-1117/20261117.typ` である。これは、Google Slides で作ったスライドを、テンプレートの試しとして写したものである。

## 作業の流れと分担

分担は最初の案で、これから話し合って直していく。

1. ユーザーが、スライドを作るよう Claude に頼む。
2. Claude が、報告日を `docs/progress/.state.json` の次回の報告日から決め、報告のフォルダを作る。報告日が未定なら、日付を `MMDD` のままにして作る。
3. Claude が、スライドの下書きを作る。
   - (1) 前回のスライドの最後の1枚（次回までの ToDo）を、2枚目にコピーする。
   - (2) 進捗ログ（`docs/progress/`）と進捗報告用の図（`results/figures/progress/`）から、詳細のスライドを作る。
   - (3) 最後に、次回までの ToDo を書くスライドを、空のまま置く。
4. ユーザーが、コピーする過去のスライドを決める。
   - (a) Google Slides で作った回は、そのスライドの画像（PNG）か1ページの PDF を、`copied/<MMDD>_p<ページ番号>.png` の名前で置く。
   - (b) Typst で作った回は、どの回の何ページかを Claude に伝える。
5. Claude が、コピーしたスライドを入れる。
6. ユーザーが、プレビューを見ながら、図と文言を直す。直したい所を Claude に頼んでもよい。
7. Claude が PDF を作り、すべてのページを確かめる。
8. ユーザーが、報告のフォルダのうち `.typ` 以外のファイルを、Drive にアップロードする。
9. 打ち合わせが終わったら、ユーザーが最後のスライドに、次回までの ToDo を書く（Claude に書いてもらってもよい）。そのあと PDF を作り直し、コミットする。Drive の PDF も新しくしたいときは、作り直した PDF を上げ直す。

### 最後のスライド（ToDo）の受け渡し

最後のスライドは、次の回の2枚目になる。11/17 の回を例にすると、次のように受け渡す。

1. 11/17 のスライドの最後に、タイトルが「11/17 → MM/DD」のスライドを、空のまま置く。次回の報告日が決まっていれば、MM/DD の代わりにその日付を書く。
2. 11/17 の打ち合わせが終わったら、このスライドに ToDo を書く。
3. 次の回のスライドを作るとき、Claude がこのスライドを2枚目にコピーする。タイトルの「MM/DD」は、次の回の報告日にする（例：「11/17 → 12/01」）。項目は、進み具合で分ける（11/17 の回では「完了」と「未着手」に分けた）。右上の「MM/DDのスライド」の表示は付けない。

Claude に任せないことは、次のとおりである。

- 過去のスライドのうち、どれをコピーするかを決めること
- 実装に関係しない事項（自分の論文の共有、学会の申し込みなど）のスライドを書くこと
- 研究の内容に関係しないこと（開発の環境やルールの整備など）をスライドに載せること。載せるときは、ユーザーがはっきり指定する。

### まだ決めていないこと

次のことは、スライドを一緒に作りながら決め、この文書と [`rules/slides.md`](rules/slides.md) に書き足す。

- スライドのデザイン（今のテンプレートは、Google Slides で使っていた見た目を写したもの）
- どこまで Claude に任せるか
- タイトルと本文の文言の指針
- 強調の図形の位置を指定しやすくする仕組み（PowerPoint のルーラーのようなもの）

## Typst の書き方（ユーザー向け）

### プレビューと PDF

スライドを直すときは、VS Code の拡張機能 Tinymist のプレビューを使う。

1. VS Code で、このリポジトリのフォルダを開く。
2. 報告のフォルダの `.typ` を開く。
3. Ctrl+K V（Ctrl+K を押してから V）で、プレビューを開く。横にプレビューが出て、`.typ` を直すたびに更新される。

プレビューの文字をクリックすると、`.typ` の対応する所へ移れる。テンプレートが `slides/template/` にあるため、プレビューが「root の外のファイルを読めない」というエラーを出すことがある。そのときは、VS Code の設定 `tinymist.rootPath` に、このリポジトリのフォルダを指定する。

PDF は、リポジトリの直下で次のコマンドを実行して作る（例は 11/17 の回）。`.typ` と同じフォルダに、同じ名前の PDF ができる。`--root slides` は、別のフォルダにあるテンプレートを読めるようにするための指定である。

```bash
typst compile --root slides slides/progress/2026-1117/20261117.typ
```

### 文の書き方

| やりたいこと | 書き方 |
|---|---|
| 段落を分ける（Google Slides の Enter） | 空行を1行入れる |
| 項や段落の中で改行する（shift+Enter） | 行の末尾に `\` を書く |
| 箇条書き（●） | 行の頭に `- ` を書く |
| 箇条書きの2段目（○、16pt） | 2文字下げて `- ` を書く |
| 番号付きの箇条書き | 行の頭に `+ ` を書く |
| 小見出し（「完了」「実装案」など、太字・24pt） | 行の頭に `= ` を書く（`= 完了`） |
| 文の中の太字 | `*太字*` |
| 小さい字の補足（16pt） | `\` で改行した後に `#note[補足]` |
| 文字の背景を薄い赤で塗る | `#hl[強調]` |
| 空の行を1行入れる | `#blank` |
| 数式 | `$y_c = (sum_i y_i D_i) / (sum_i D_i)$` |
| 記号 `*` `#` `_` `$` `\` そのもの | 前に `\` を付ける（`\*`） |

- 1つの段落は、途中で改行せずに1行で書く。ソースの改行は、日本語の文字の間でも空白になるためである。
- 数式の書き方が分からなければ、Claude に LaTeX の書き方で伝えて、書き換えてもらう。

例（11/17 の8ページ目に近い形）：

```typst
#slide(title: [自動追跡の外れ値の解析], title-note: [(11/12追記)])[
  - 画面中央の2, 3点を溝底の点として誤検出したことが判明 \
    #note[（ギリギリ溝底と言える場所には位置している）]
  - 溝底の下側に暗い部分が生じているのが原因

  →*点の抽出方法を見直したい*
]
```

### 図を置く

図は `fig-at` で、決まった範囲に置く。図は範囲に収まる最大の大きさになり、下にファイル名が自動で付く。

```typst
#fig-at(..cell-left(), image("figures/a.png"))
#fig-at(..cell-right(), image("figures/b.png"))
```

`cell-left()` の前の `..` は、値の組をばらして、別々の引数として渡す書き方である。`cell-left()` は、図を置く範囲を、4つの値の組 (x, y, 幅, 高さ) として返す。一方、`fig-at` は、この4つを別々の引数として受け取る。そこで `..` を付けて、組を4つの引数に分けて渡す。MATLAB で cell 配列を `c{:}` と書いて、要素を別々の引数として渡すのと同じである。`..` を付けないと、組全体が1つ目の引数（x）として渡り、エラーになる。次の2行は、同じ意味である。

```typst
#fig-at(..cell-left(), image("figures/a.png"))
#fig-at(31.3pt, 150pt, 323.5pt, 248pt, image("figures/a.png"))
```

| 範囲 | 置く所 |
|---|---|
| `cell-left()`・`cell-right()` | 左右に2枚並べる |
| `cell-full()` | 本文の幅いっぱいに1枚（横長の図） |
| `cell-side()` | 右に1枚。左の文は `#side-text[...]` に書く |

- 範囲の上端は、既定では 150pt（本文2行の下）である。上の文が長くて図と重なるときは、`cell-left(top: 180pt)` のように変える。
- 図の一部だけを見せるときは、`crop: (左, 上, 右, 下)` を付ける。値は、図の幅・高さに対する割合（0〜1）である。
- `image()` には、大きさ（`width`・`height`）を付けない。
- 文を左右2列に分けて図の上に書くときは、`#cols[左の文][右の文]` と書く。列の幅は、左右の図の範囲とそろう。

### 強調の図形

図の上の図形は、`fig-at` の `marks:` に書く。位置と大きさは、図の幅・高さに対する割合（0〜1）で書く。PowerPoint と同じく、図形を囲む四角の左上 (x, y) と、幅・高さで指定する。

```typst
#fig-at(..cell-right(), image("figures/b.png"),
  marks: (mark-oval(0.42, 0.48, 0.22, h: 0.09),))
```

図と図の間の矢印や、スライドの上の文字は、`#draw(...)` で描く。座標は、スライドの左上を原点とする pt で書く。スライドの大きさは 720pt × 405pt である。

```typst
#draw(
  mark-arrow((328pt, 272pt), (392pt, 272pt)),
  mark-text(344pt, 250pt, [拡大]),
)
```

| 図形 | 書き方 | 既定 |
|---|---|---|
| 丸・楕円 | `mark-oval(x, y, 幅, h: 高さ)`（`h` を省くと円） | 赤、0.75pt |
| 四角 | `mark-rect(x, y, 幅, 高さ)` | 赤、0.75pt |
| 線 | `mark-line((x1, y1), (x2, y2))` | 赤、0.75pt |
| 矢印 | `mark-arrow((x1, y1), (x2, y2))` | 黒、1.5pt |
| 文字 | `mark-text(x, y, [文字])` | 黒、14pt |
| 吹き出し（白塗り・黒枠） | `mark-callout(x, y, [文字])`（`center: true` で中央揃え） | 20pt |

線の太さは `stroke: thick` のように変えられる。`thin`（0.75pt）・`medium`（1.5pt）・`thick`（3pt）は、Google Slides の 1px・2px・4px にあたる。色は `color: black` のように変える。

### 過去のスライドをコピーする

Google Slides で作った回のスライドは、画像を `copied/` に置き、次のように書く。右上に赤字で「11/03のスライド」と付く。

```typst
#copied-slide(image("copied/1103_p9.png"))
```

Typst で作った回のスライドは、その回の `.typ` から `#slide(...)` をコピーし、`copied-from: "11/03"` を足す。文言を後から直せる。

## PowerPoint の図

アルゴリズムの説明図のように、GUI で描きたい図は PowerPoint で作る。

1. `.pptx` を `slides/diagrams/` に置く。
2. 図を PNG で書き出し、同じフォルダに同じ名前で置く。名前は、何の図かが分かる英語にする（例：`grooveTrackingAlgorithm_step1`）。
3. スライドで使うときは、PNG を報告のフォルダの `figures/` にコピーする。

過去の回の図を使い回すときも、`slides/diagrams/` から探す。

## テンプレート（progress.typ）の中身

テンプレート [`slides/template/progress.typ`](../slides/template/progress.typ) は、スライドの見た目をすべて決める。大きさや色を変えたいときは、ユーザーがこのファイルを直してよい（Claude は、ユーザーに確かめてから直す）。

テンプレートを直すと、過去の回の `.typ` をコンパイルし直したときに、その回の見た目も変わる。過去の回の PDF はコミットしてあるので、作り直さなければ変わらない。

### 読むのに要る Typst の書き方

- `#let 名前 = 値` は、変数を定義する。
- `#let 名前(引数, 名前付き引数: 既定値) = 中身` は、関数を定義する。名前付き引数は、呼ぶときに `top: 180pt` のように名前を付けて渡す。省くと既定値になる。
- `set` は、その後の要素の既定の設定を変える。例えば `set text(size: 20pt)` は、その後の文字を 20pt にする。
- `show` は、ある種類の要素の見せ方を変える。
- `place` は、文の流れと関係なく、決めた位置に置く。
- `context` は、図の大きさを測ったり、ページ番号を読んだりする所で使う。
- `(W, H) => {...}` は、名前の無い関数である。
- `_` で始まる名前は、テンプレートの中だけで使う補助の関数である。

### ファイルの並び

テンプレートは、上から次の順に並んでいる。

1. 値の定義：寸法（`body-left` など）、色、文字の大きさ、線の太さ、行の送り（`line-gap`・`para-gap`）、フォント（`fonts`）。見た目の数値は、ほとんどがここにある。各行のコメントに、値の意味が書いてある。
2. 全体の設定：`progress-slides`
3. 位置の指定：`at`、`_resolve`
4. 強調の図形：`mark-oval` などと `draw`
5. 文字の飾り：`hl`、`note`、`blank`
6. 図：`fig-at`、`fig`
7. 図の配置の型：`cell-left` など
8. スライド：`title-slide`、`slide`、`blank-slide`、`copied-slide`

テンプレートの中の座標は、スライドの左上を原点とする pt で書いてある。`at(x, y, 中身)` が、ページの余白の分を差し引いて、中身をその座標に置く。

### 主な関数

- `progress-slides(body)`：全体の設定をする。各回の `.typ` の先頭で `#show: progress-slides` と書くと、その後ろのすべてにこの設定がかかる。決めていることは、次のとおりである。
  - ページの大きさ（720pt × 405pt）と余白。余白は、本文の左端・右端・上端に合わせてある。下の余白は 0 である。
  - ページ番号の位置と色。ページ番号は `foreground`（ページの一番上の層）に描くので、図や過去のスライドの画像に隠れない。
  - 文字のフォントと大きさ、行の送り、段落の間。`top-edge`・`bottom-edge` は、1行の箱の高さを文字の大きさにそろえる設定である。行の送りを Google Slides に合わせるために使っている。
  - 箇条書きの記号（●・○）と字下げ。`show list:` の中の設定は、2段目の箇条書きにかかる（文字を 16pt にし、字下げを変える）。
  - 番号付きの箇条書きの字下げ。
  - 小見出し（`= 完了`）の見た目。Typst の見出しの書き方を、太字・`subhead-size`（24pt）の小見出しとして見せる。前後は、段落の間と同じだけ空ける。
- `mark-oval`・`mark-rect`・`mark-line`・`mark-text`・`mark-callout`・`mark-arrow`：強調の図形を作る。どれも、図形をその場では描かない。代わりに、「基準の幅 W と高さ H を受け取って図形を描く関数」を返す。
  - `fig-at` の `marks:` に渡すと、図の大きさを基準にして描かれる。`draw` に渡すと、スライドの大きさを基準にして描かれる。
  - 座標に数（0〜1）を渡すと、基準に対する割合として扱う。長さ（pt）を渡すと、そのままの長さとして扱う。この換算は `_resolve` がする。
  - `mark-arrow` は、線と三角形（矢じり）を組み合わせて描く。矢じりの長さは線の太さの4.6倍、矢じりの幅の半分は1.7倍である。Google Slides の矢印に合わせた値である。
  - `mark-callout` は、白で塗って黒い枠を付けた箱に、文字を入れる。
- `fig-at(x, y, w, h, img, crop:, marks:, caption:)`：図を、(x, y) を左上とする幅 w・高さ h の範囲に、収まる最大の大きさで置く。次の順に処理する。
  1. 図の元の縦横比を測る（`measure`）。
  2. 切り出す範囲（`crop`）があれば、切り出した後の縦横比を求める。
  3. 図の下に書くファイル名の高さを測り、範囲の高さから引く。
  4. 範囲の幅と、残った高さの両方に収まる、図の幅を求める。
  5. 図の本体とファイル名を縦に並べ、範囲の中で左右中央・上寄せに置く。
- `_figure-body`：`fig-at` と `fig` が使う、図の本体を作る関数である。切り出すときは、図を元の大きさのまま箱に入れ、見せる範囲の外を切り落とす（`clip`）。強調の図形は、切り出した後の図の大きさを基準にして描く。
- `fig(img, width:, height:, crop:, marks:, caption:)`：`fig-at` と同じく、図とファイル名を描く。ただし、決まった範囲ではなく、本文の流れの中に置く。大きさは `width` か `height` で決める。どちらも省くと、本文の幅になる。
- `cell-left`・`cell-right`・`cell-full`・`cell-side`：図を置く範囲を、(x, y, 幅, 高さ) の組で返す。範囲の上端の既定値（150pt）、下端の既定値（`fig-bottom` の 398pt）、`cell-side` の左端の既定値（380pt）は、これらの関数の引数の既定値で変えられる。
- `title-slide(date:, author:)`：表紙を作る。「進捗報告」と、日付・氏名を、決まった位置の箱の中に、中央揃えで書く。
- `slide(title:, title-note:, copied-from:, body)`：タイトルと本文のスライドを作る。
  - 新しいページを始め、タイトルを決まった位置に太字で書き、その下に線を引く。タイトルの文字には、`title-stroke`（0.6pt）の縁取りを足して太く見せる。
  - `title-note` は、タイトルの後ろに細い字で続ける。
  - `copied-from` があれば、右上に「MM/DDのスライド」と書く。
  - 本文は、ページの余白の内側（本文の左上）から書き始める。
- `copied-slide(img, from:)`：過去のスライドの画像を、スライド全体に置く。
  - ファイル名の先頭の `<MMDD>` から、「MM/DDのスライド」の日付を作る。ファイル名がこの形でなければ、エラーで止める。
  - 画像に元からある右上の表示とページ番号は、白い四角で隠してから描き直す。

### よくある直し方

| 変えたいこと | 直す所 |
|---|---|
| タイトルの文字の大きさ・太さ | `title-size`、`title-stroke` |
| 小見出しの文字の大きさ | `subhead-size` |
| 本文、箇条書きの2段目・補足の文字の大きさ | `body-size`、`sub-size` |
| 段落の間、段落の中の行の送り | `para-gap`、`line-gap` |
| 図の下のファイル名の大きさ・色 | `caption-size`、`caption-color` |
| 強調の図形の色、線の太さ | `mark-color`、`thin`・`medium`・`thick` |
| フォント | `fonts` |
| 箇条書きの記号と字下げ | `progress-slides` の中の `set list(...)` |
| 図の範囲の上端・下端の既定値 | `cell-left` などの引数の既定値、`fig-bottom` |
| タイトルの位置・下の線 | `slide` の中の `at(...)` |

直したら、11/17 の回などをコンパイルして、見た目を確かめる。
